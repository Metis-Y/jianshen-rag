# 健身管家（FitPal）· RAG 私人健身助手

基于私有文档 + 个人数据的健身管家：上传训练计划/营养资料，记录每天的训练与体重，
用自然语言提问——**计划怎么排带引用、效果趋势有数据、饮食怎么调结合你的记录**。

**定位原则：业务驱动 · 闭环优先 · 技术够用即可。**
先让「上传资料 + 记录数据 → 问出带出处的答案 + 问我自己的趋势」这条闭环成立，不追求技术深度。

## 三条业务主线

| 主线 | 输入 | 能力 | 数据来源 |
| --- | --- | --- | --- |
| **计划** | 训练计划 / 动作原理文档 | "深蹲日怎么安排"带引用回答 | RAG（Chroma） |
| **效果** | 每日训练日志 + 体重记录 | "这周容量趋势 / 体重变化"文字总结 | 结构化（SQLite） |
| **饮食** | 营养资料 + 每日饮食记录 | "减脂期晚餐怎么吃"引资料 + 结合忌口/记录 | RAG + 结构化 |

## 业务闭环

```
注册/登录
→ 上传资料（训练计划/营养文档，状态可见，失败给原因）
→ 每日记录（训练 / 体重 / 饮食）
→ 提问（计划饮食带引用；效果带自己的数据）
→ 周报总结（LLM 基于聚合数据生成文字趋势）
→ 回看历史 / 点赞踩 / 删除资料（删后问不到）/ 改记录（统计跟着变）
```

**五条验收标准**：

1. 上传《腿部训练计划》后问"深蹲日怎么安排" → 回答引用该文档
2. 记录 3 天训练 + 体重后问"我这几天的训练容量和体重趋势" → 回答基于我的数据，不胡编
3. 删除某份营养资料后问相关内容 → "知识库中没有相关内容"
4. 问"减脂期晚餐怎么吃" → 引用营养资料，且结合我记录过的忌口
5. 历史会话可回看、反馈可记录、统计正确

## 技术栈（与 interview-rag 完全同构，零新增）

| 层次 | 技术 |
| --- | --- |
| 后端 | FastAPI + uvicorn、SQLAlchemy 2.x、SQLite |
| 向量库 | ChromaDB（本地持久化，单 collection + owner_id 过滤） |
| 文档处理 | LangChain（loader + splitter） |
| 模型 | 硅基流动 API（bge-m3 Embedding + DeepSeek/Qwen） |
| 认证 | JWT（pyjwt，单用户体系） |
| 流式 | SSE（FastAPI StreamingResponse） |
| 前端 | Vue 3 + Vite | dev 用 vite proxy，演示由 FastAPI 托管 dist；nginx 仅作可选部署层 |

**刻意不做（一期画线）**：图表库、OCR、动作视觉纠错、混合检索、评估、消息队列、RBAC/团队共享。

## 与“知识库问答”的关键差异

普通 RAG 答"文档里怎么写"；本项目的效果主线答"**你本人怎么样、接下来怎么调**"——
LLM 同时引用资料向量和自己的结构化日志，这是比纯文档问答多出的一层技术增量。
