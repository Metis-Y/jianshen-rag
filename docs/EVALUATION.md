# 评估手册（Evaluation Guide）

> 给评审/面试/自查用。回答四个问题：评什么、怎么跑、怎么看结果、怎么加题。
> 配套：题库 `tests/eval_set.json`、脚本 `scripts/run_eval.py`、规划见内部 08 文档。

## 1. 评估体系（两级）

| 级别 | 测什么 | 工具 | 成本 | 状态 |
| --- | --- | --- | --- | --- |
| ① 检索评估 | 期望文档有没有进 top5，排名如何 | `scripts/run_eval.py` | 只调 embedding，零对话模型成本 | ✅ 已上线（59 题） |
| ② 端到端评估 | 完整回答是否覆盖题库预写的"答案要点" | 规划中（LLM-as-judge） | 每轮 2 次生成 | 待开工（见 08 文档） |

## 2. 检索评估怎么跑

前置：demo 账号与公共知识库已就绪（`python scripts/seed_demo.py`）、`.env` 有可用的
embedding key、网络可达。

```bash
cd D:/rag_project/jianshen-rag
./.venv/Scripts/python.exe scripts/run_eval.py
```

机制要点：
- 脚本直接调用线上检索 `index.retrieve()`（含 rerank 重排 + 按文档去重），**测的就是
  真实问答用的那条链路**，不是另起炉灶；
- 以 demo 账号的可见口径跑（个人 3 篇 + 公共 23 篇）；
- 每题只做一次检索（embedding 偶发失败自动重试一次）。

**对比实验**（改检索方案后必做）：

```bash
# 关掉重排，复现粗排基线
RERANK_API_KEY="" ./.venv/Scripts/python.exe scripts/run_eval.py
# 对照两次输出的指标变化
```

## 3. 指标怎么读（面试口径）

| 指标 | 含义 | 参考值（58 题时的记录） |
| --- | --- | --- |
| top1 命中率 | 排名第一的就是期望文档的比例 | 粗排 67% → 重排 83% |
| top3 命中率 | 期望文档进入前 3 的比例 | 91% → 98% |
| top5 命中率 | 期望文档进入前 5 的比例（主指标） | 95% → 98% |
| MRR | 每道题"1 ÷ 期望文档最好排名"的平均；1.0=全部排第一 | 0.786 → 0.897 |
| 平均不同文档数 | top5 中不重复文档数（满分 5）；低于满分=某文档多切片霸占引用位 | 4.14 → 4.28 |

一句话总结：**top5 看"找不找得到"，MRR 看"排得准不准"，不同文档数看"来源多不多样"。**

读报告顺序：总指标 → 按题型分组（找短板题型）→ 未命中清单（逐题查因）。

## 4. 未命中怎么查因

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 期望文档整题未进 top5 | 语料里确实没有该知识点 | 补语料（先改语料再重建公共库） |
| 期望文档进了但排名低（old 蛋白质题） | 知识点多处出处，`expectDoc` 唯一性有歧义 | 改用 `expectDocs`：列出所有正确出处，命中任一计入 |
| 个人资料题被公共语料挤掉 | top5 名额竞争 | 观察组内趋势；必要时考虑个人/公共配额（议题） |
| 同义表述题（"怎么吃" vs 语料"摄入建议"） | 检索对措辞敏感 | 属正常波动，看整体指标勿盯单题 |

## 5. 怎么加题

`tests/eval_set.json` 每道题字段：

```json
{
  "question": "问题原文（用户真实问法，自然语言）",
  "expectDoc": "期望命中的文档标题（单一出处时用这个）",
  "expectDocs": ["标题A", "标题B"],   // 多出处时与 expectDoc 二选一，命中任一即可
  "tag": "常识 | 精确词 | 训练进阶 | 有氧进阶 | 补剂与营养 | 人群与场景 | 恢复与评估"
}
```

出题纪律：
1. 新语料入库后，先为它补 2~4 题（覆盖它的标题被覆盖）；
2. "精确词"类保持一定比例——它是纯向量检索的软肋探针；
3. 知识点确实多出处时用 `expectDocs`，别硬指定单一文档；
4. 题目用用户会说的自然语言，别用语料里的原文复述。

## 6. 决策阈值（何时要动手改检索）

- top5 ≥ 0.9 且 MRR ≥ 0.85：检索健康，不动；
- top5 掉到 0.85 以下 或 某 tag 组明显塌方：查语料与瓶颈（重排参数、配名额、或再议混合检索）；
- **每次改检索方案，前后两次跑分数字写进内部 06 文档决策记录**（如 rerank 那次）。

## 7. 诚实的边界（面试可主动说）

- 这是**文档级**命中口径，不测"答案写得好不好"——由端到端评估补；
- MRR/命中率随语料规模变化，扩容后应重跑，不拿旧数字说事；
- 评估跑在 demo 可见口径（个人+公共），真实用户的自有文档多寡会不同。
